# Release candidate 1 (2026-11-02)

Compare against the WE baseline: `we-baseline-2026-11-01...handoff-2026-11-02-rc1`.
Everything below was tested in game (single player, test bundle) and confirmed working.

## Community Buildworks

New content
- `70_kbwcb_refrigeration_tiers.json`: 59 buildables under Appliances > Refrigeration, 12 catalog
  cards (tiers and shells in build order), built from the KBW Vanilla Expanded refrigerators.
  - 8 standard fridges: 60/30 (single build), 80/40 and 100/50 (shell, then unit).
  - Mini Refrigerator: 30/8, 40/12, 50/15.
  - Industrial + White Industrial freezer-only (both compartments freeze): 30/30, 65/65, 100/100.
  - Chest Freezer 65 / 100 (KBW's own covers 30).
  - Build time 200, blowtorch 5 uses, every stage under 75 carry weight.
- Reinforced counters / upper cabinets / wall cupboards (military-crate cost, capacity 100),
  added in files 35, 40, 41, 42.
- Shell sheet `KBWCommunityIceShell` grows from 4 to 44 tiles (same pack and tiledef 8181, so
  no mod.info change; the `pack=` / `tiledef=` lines from the previous hand-off are still needed).
  New `common/media/depthmaps/DEPTH_KBWCommunityIceShell.png`.
- "Build first: <shell name>" translations (`IGUI_KBW_Vanilla_<shell id>`) for the ice machine
  and fridge shells.

New runtime Lua (please review)
- `lua/shared/KBWCommunity_StageProperties.lua`: registers two KBW stage properties through
  KBW's public `Properties.register`: `kbwcbContainerCapacity` (capacity per container type; KBW's
  own `container` only sets the first container) and `kbwcbContainerTypes` (retypes the fridge
  compartment to freezer for the freezer-only fridges).
- `lua/client/KBWCommunity_StageInfo.lua`: wraps KBW `BuildableInfo.containerTiles` so the build
  menu shows the real capacities (KBW reads the tile properties), and wraps
  `ISToolTipInv.render` to add a name + storage box to picked-up builds.
- `lua/shared/KBWCommunity_Pickup.lua`: wraps `ISMoveableSpriteProps` pickUpMoveableInternal /
  instanceItem / placeMoveableInternal. Picking up one of our builds stores its container types
  and capacities on the item; placing it restores them (before this, everything reverted to the
  tile's vanilla values). Only touches objects whose KBW build id starts with `community.`,
  `tikitown.`, `worldessentials.tikitown.` or `kbwcb.`.
- `lua/shared/KBWCommunity_Rotation.lua`: sets moveable face offsets (`Noffset` etc.) on 242
  sprites at load. The engine only generates them when a tileset groups <= 4 tiles under one
  GroupName + CustomName; Dirkies groups up to 52, so those counters couldn't be rotated when
  placed from the inventory. Offsets come from our KBW definitions.

## TikiTown Buildworks
- Reinforced counters (58) in `23_tikitown_furniture.json`.
- `KBWTikiTown_Pickup.lua`, `KBWTikiTown_Rotation.lua` (16 sprites), `KBWTikiTown_StageInfo.lua`:
  same code as the Community files under our own names, so the submods never shadow each other.
  Each hook has an install guard, so loading both submods installs it once.

## Not tested
- Multiplayer (all tests were single player).
- Multi-tile pieces that pick up as one item (none of the new content).

## Removed
- 2-tile two-stage builds (popsicle freezer): WE's placement check only waives collisions on the
  anchor tile of a replacement, so a 2-tile shell can't be finished. Never shipped.
